# IOPSTOR CMS — architecture spec (current state, 2026-09-15)

**What this file is.** The map an agent reads before touching anything: what exists, where it lives, and *why* it has the shape it has. The territory is the source, and the long-form developer reference is `docs/TECHNICAL.md` (§ numbers below point into it). Client brief and client decisions: `requirements.md`. Rules and commands: `CLAUDE.md` (repo root).

**Keeping it true.** Every PR that changes the shape of the system updates this file in the same PR (CLAUDE.md rule 3), and `/after-merge` audits it against the merged diff after every merge (rule 4). If a statement here and the source disagree, the source wins — fix this file in the next PR.

## 1. Stack and platform

| Piece | Choice |
|---|---|
| App | Python 3.13, Flask 3.1, Jinja2; one public stylesheet, no JS on the public site, no build step |
| Data / auth / files | Self-hosted **Supabase**, reached **only through its Kong gateway** with `supabase-py` 2.x and the service-role key: PostgREST for rows, GoTrue for logins, Storage bucket `media` for uploads **and reads**. Only this app ever talks to it — a browser does not, not even for a picture (§7 `/media/`). No direct Postgres, no ORM — rows are dicts |
| Tokens | PyJWT verifies Supabase access tokens locally (HS256, `SUPABASE_JWT_SECRET`) |
| Packaging | pipenv (`Pipfile`, `Pipfile.lock`, in-project `.venv/`); `requirements.txt` / `requirements-dev.txt` are **generated from the lock** and are what Docker installs |
| Deploy | Dokploy → `Dockerfile` (python:3.13-slim, `gunicorn` only — migrations are the compose stack's one-shot `migrate` service, which `app` waits on with `condition: service_completed_successfully`, so they run once per deploy and never on a restart; workers from `GUNICORN_CMD_ARGS` — `-w 2 --threads 8 --preload --access-logfile -` by default, `-w 30` in Dokploy; the app is stateless across workers, TECHNICAL.md §15) |
| Production | **One Dokploy Compose service** from `docker-compose.yml`: `migrate` (one-shot, `flask migrate`) + `app` (that Dockerfile) + `cloudflared`, GitHub `primesukh/iopstor` as the source, `https://www.iopstor.com`. Supabase from Dokploy's own template, a separate stack, reached at `http://<kong-service>:8000` over the external `dokploy-network`. **Two ingresses on purpose**: the tunnel for the public site and **Dokploy's own Traefik** (a domain attached on `app` in the Dokploy UI — it leaves no trace in `docker-compose.yml`, which is why `10.0.1.7` in the audit log had to be measured rather than read off the file) for LAN access to the admin. `app` still publishes no port. What makes a forwarding header trustworthy is `TRUSTED_PROXIES`, not the absence of a second route (the throttle row in §14, TECHNICAL.md §12). `cloudflared` sits behind `profiles: [tunnel]`, so the stack also deploys before a tunnel exists (`COMPOSE_PROFILES=tunnel` turns it on); a Dokploy domain on `app` is the alternative to the port when the LAN wants a name. Runbook: TECHNICAL.md §15 |
| Tests | pytest; `tests/test_offline.py` always, the rest marked `live` and skipped without `SUPABASE_*` in `.env` |
| Admin JS | `static/admin.js`, plain browser JavaScript, progressive enhancement, no build step; five vendored libraries in `static/vendor/` — SortableJS 1.15.6, Quill 2.0.3 (+ `quill.core.css`), supabase-js 2.116.0, Yjs 13.6.32 and y-quill 1.0.0 (the last two as `.mjs`; `y-quill.mjs` imports `./yjs.mjs` by relative path so there is exactly one copy of Yjs). `tests/reconcile.mjs` runs the shared-document section of `admin.js` against the real Yjs under node |

Rejected on the way (user decisions, see git history): SQLAlchemy + psycopg over `DATABASE_URL`, Alembic, Flask-Admin, uv, a CDN-loaded editor, a JS framework anywhere.

## 3. Tables (`migrations/0001_initial.sql` + `0003`–`0013`)

| Table | Purpose / notable columns |
|---|---|
| `post_types` | content types **as rows**: `slug, name, url_prefix ("" = top-level pages), hierarchical, field_schema [{key,label,type,required}], taxonomies [slugs], jsonld_type, in_sitemap, has_pages (0005)` |
| `posts` | everything editable: `post_type_id, parent_id, slug, title, excerpt, blocks [{type,data}], meta {}, seo {title,description,canonical,robots,og_image}, status draft/published, published_at (future = scheduled), featured_media_id, author_id, menu_order`; unique `(post_type_id, slug)`. A block's `data` also carries two keys nobody types: `_id` (names the section across browsers) and `_rich` (the Quill verdict) — both in `blocks._NON_TEXT_KEYS`, §5 |
| `taxonomies`, `terms`, `post_terms` | classification; `post_terms` has a composite PK so PostgREST can embed `terms(*)` |
| `media` | `key` (bucket path), `url` (**`/media/<key>`, the path this app serves it at — not the Storage address**), `filename, mime, size, alt, uploaded_by` |
| `users` | `id` = GoTrue `sub`; `email, name, role editor/admin` — the row is what grants CMS access |
| `leads` | `kind contact/quote/career, name, email, phone, company, message, post_id, data {}, status new/in_progress/handled` |
| `warranties` (0003, 0004) | `serial`, `serial_key` = `upper(btrim(serial))` **generated, unique** (the lookup key: case- and space-insensitive, exact `.eq()` because serials may hold `%`/`_`), `customer_name, email, purchase_date, expiry_date, amc, remarks, remarks_public`; CHECK `expiry_date >= purchase_date` added `NOT VALID` |
| `settings` | `key` → JSON `value` (site_name, tagline, logo_url, default_og_image, social_links, ga_id, contact_email, contact_phone, address, robots_extra, notify_email) |
| `menus` | `slug` header/footer → `items [{label, url, children}]`, one level |
| `redirects` | `from_path → to_url`, `code`, `hits` |
| `payments` | `provider, provider_ref, post_id, lead_id, amount, currency, status, raw` |
| `audit_log` (0008) | **who did what, and what it was before**: `at, user_id (no FK), user_email, ip, action create/update/delete/restore/login/logout/login_failed, table_name, row_id (text), label, changes {field: [was, now]}`. `BIGINT GENERATED ALWAYS AS IDENTITY`, `TEXT` not `VARCHAR(n)`, and **append-only by trigger** (`audit_log_no_change` raises on UPDATE or DELETE) — the app holds the service-role key and could otherwise rewrite its own evidence. One index, `(user_id, id DESC)` |
| `post_drafts` (0010) | **the unpublished edits of one page**: `post_id` PK (cascades from posts), `blocks {}`, `state` (base64 `Y.Doc`, written by the elected writer; the truth a reload restores from), `updated_at` (moddatetime), `updated_by`, `updated_by_email`. `posts.blocks` stays the **published** content and every public reader goes on reading it |
| `post_sessions` (0010) | **one person's open sitting on one page**, so the log can still say what each editor changed once autosave has removed the per-Save entry: `(post_id, user_id)` PK, `user_email`, `ip` (copied — the flush runs inside somebody else's request), `changes {field: [was, now]}`, `started_at`, `updated_at`. Index on `updated_at`, the only query besides "this page's" |
| `schema_migrations` | applied file names, created by the bootstrap |

RLS is on for every table (`0002`; a new table repeats the one `ENABLE ROW LEVEL SECURITY` line, no policies) so the anon key sees nothing; the service-role key bypasses it. NOT NULL columns carry defaults; `updated_at` via `moddatetime` triggers.

**`field_schema` types in use:** `text, textarea, number, date, url, media, json, kv`. Nothing validates the list — an unknown type falls through to a text input, so adding one is additive. `kv` (0006) is label/value rows stored as an ordered **array** `[{k,v}]`, because `jsonb` sorts an object's keys and a spec table must keep its order.

**`posts.status` has a third value, `trash` (no migration — the column is a plain varchar).** Deleting a post moves it there; the row, its id, its children's `parent_id`, its `post_terms` and its leads all survive, which re-creating a row could not manage. It needed no new filter because every public read goes through `db.live()` (`status='published'`). The places that *did* need one are the four that were not filtering by status — `admin_ui.posts()`, `admin_ui.dashboard()`, `admin_api.list_posts()`, `db.admin_counts()` — plus `admin_ui.edit_post()` and `admin_api._post_or_404()`, which 404 a trashed post so **Save** cannot silently un-trash it. `unique_slug()` still counts a trashed slug as taken, which is what makes restore collision-free.

**Seeded types:** `page ""`, `post blog`, `service services` (hierarchical), `case_study case-studies`, `event events`, `partner partners` (`has_pages=false`), `datasheet datasheets`, `product products` (price in rupees, `specs` kv, `sku`, `datasheet_media_id`).

**Migrations.** One numbered `.sql` per schema edit, applied in name order by `flask migrate` through the `apply_migration(name, sql)` RPC (SECURITY DEFINER, service_role only, one transaction per file; `0000_bootstrap.sql` creates it and is pasted into Studio once). Only `[0-9][0-9][0-9][0-9]_*.sql` is a step (`MIGRATION_GLOB`); two hand-run scripts carry no number and so are never a step: `repair_schema_migrations.sql` for a database built by pasting files before the ledger existed, and `purge_test_audit_rows.sql`, the only sanctioned delete from the append-only `audit_log` (`migrate()` names it when a run fails with "already exists"). Agents never apply migrations — see `/migration`.

**A content migration (`0011`) is the other shape a numbered file takes:** no column changes, rows are rewritten. Three rules it set, all in its own header: match rows by **content, never by id** (production has its own ids, and a page somebody already rewrote by hand matches nothing and is left alone); rewrite `post_drafts.blocks` **and clear `post_drafts.state`** in the same transaction, because `initShared()` loads the stored `Y.Doc` in preference to `blocks` and a stale one puts the old shape straight back on the next open; and strip `data._rich` from every `rich_text` block whenever what `quillKeeps()` accepts has changed, because the verdict is stored and never recomputed. Safe to run twice only because the second run matches nothing. Where it runs: on dev the user applies it by hand; in production the compose stack's one-shot `migrate` service applies every unapplied file on the next deploy (§1), so "needs applying" means two different things for the two databases.

## 4. Data access contracts

- `db.select_posts()` embeds `post_type:post_types(*)`, `featured_media:media(*)`, `terms(*, taxonomy:taxonomies(*))` in one round trip; term filtering adds `post_terms!inner(term_id)`.
- `db.with_paths()` / `db.hydrate()` attach `path` from a per-request hierarchy index; a `has_pages=false` type gets `path=None`, and *that one value* is what removes its detail page, sitemap entry, `.md` twin, card link and JSON `url` — no per-feature checks.
- `db.live(q)` = `status='published' AND published_at <= now()`; every public query goes through it.
- `db.tree(type)` = top-level live posts with `children`, memoised per request; feeds the header mega panel, the services archive and `post_list(top_level)`.
- **Two caches.** `db._cached()` is per request on `flask.g` (derived things: `tree()`, `seo.site()`, `admin_counts()`). `db._proc_cached()` is per worker process and survives requests — `post_types()`, `settings()`, `get_menu()`, `get_media()`, `redirect_for()` — because those round trips dominated the public site (measured: `GET /` was **29 round trips, 219 ms**, 17 of them one-per-picture `get_media()` and 2 an entirely uncached `get_menu()`). Cross-worker invalidation is **one file's mtime on `/dev/shm`** (`bump_epoch()`/`content_epoch()`, throttle.py's trick): every write touches it, every read compares it, a stat on tmpfs is microseconds. Called from `insert()/update()/delete()` — the same funnels the audit log uses — plus the three writers that bypass them (`set_settings`, `set_menu`, `set_post_terms`); **never** from `save_draft()`/`touch_session()`, which are autosaves and would empty every cache every few seconds while somebody types. `bump_epoch()` also drops the request's own `_cached()` memos, because a writer reads the old row first for its audit diff and thereby caches the value it is about to invalidate (caught by `test_terms_settings_menus`). (TECHNICAL.md §4, §8, §15, §17.)
- `db.update(..., if_unchanged=<updated_at>)` is the optimistic-concurrency guard, and it is a **filter on the UPDATE** (`WHERE id=? AND updated_at=?`), never a compare in Python — thirty stateless workers share no memory, so only Postgres can decide it. No rows back ⇒ `None` ⇒ no audit row, because `_audit()` already sits behind `if after:`. The token maintains itself (the `posts_updated_at` moddatetime trigger). **Deliberately not passed by** `PATCH /posts/<id>`, `flask seed --reset-content`, and `/admin/audit/<pk>/restore` — a restore is an intentional overwrite, which is the whole point of the button. Only `posts` is covered; `settings`/`menus` go through `set_settings()`/`set_menu()` and are still exposed.
- `db.get_draft()/save_draft()/clear_draft()` and `touch_session()/flush_sessions()/open_sessions()` are the working draft. **`save_draft()` and `touch_session()` are the only writes in the app that are not audited**, and deliberately: `audit_log` has no retention job and `_diff()` stores the whole `blocks` array on both sides of every row, so an autosave through `update()` would add a full page copy every second or two per editor for ever. The record is deferred, not dropped — `flush_sessions()` writes **one** row per person per sitting, passing `user=`/`ip=` from the session row rather than the request, because with no scheduler a stale session is closed by whoever next touches the page (usually a different editor). Publish (`action="publish"`) and Discard are audited normally.
- `db._tolerate_0010()` is how the app runs before `0010` is applied, and the code in it is **`PGRST205`**, not Postgres's `42P01`: PostgREST answers from its schema cache and never reaches the table. Measured — assuming `42P01` made the editor raise instead of falling back. Anything that is not a missing table still raises.
- Never `.delete()` without a filter — PostgREST would truncate the table.
- Order of every list: `menu_order`, then `published_at desc`. `menu_order` is not in the admin form (only the seed and `PATCH /posts/<id>` write it).

## 5. Blocks (`iopstor/blocks.py` — the only place a block type is declared)

Two keys in a block's `data` are not fields: `_id` names the section for as long as it exists and `_rich` stores the Quill gate's verdict (§10). Both are in `_NON_TEXT_KEYS`, which also reaches the browser as `EDITOR["scalars"]` — that one list is how the editor decides what is prose (a string whose key is not in it becomes a shared text type) and how `blocks_text()` decides what to skip. `validate_blocks()` ignores extra `data` keys by design.

`BLOCKS = {type: (required, optional)}`, twenty types: `hero, rich_text, image, gallery, cards, columns, cta, faq, stats, testimonial, embed_html, post_list, spec_table, definitions, points, contact_form, pdf, warranty_check, spacer, divider`. `definitions` and `points` (2026-09-15) are the design's two non-prose sections given types of their own — a term/description list and a heading-intro-list-button panel — because written as `rich_text` carrying their own classes they could never join the shared document (§10). Each has `templates/blocks/<type>.html` wrapped `<section class="section{{ cls }}"{{ sty }}{{ fe() }}><div class="wrap">…`.

**Alongside `BLOCKS`:** `EDITOR` (widgets per field, repeater `items` subfields, labels, `kinds`, `choices` = `[value, label]` pairs for the generic `choice` dropdown, `order` of the picker, `names` = icon + plain name + one-liner, `seed` = starting content that must pass `validate_blocks`), `REPEATERS`, `LAYOUTS` (three starting page shapes), `NEVER_NESTED = ("columns", "hero")` (mirrored in `admin.js`), `MD_SKIP = ("embed_html",)`.

**Layout keys on any block's `data`:** `align`, `align_box`, `width` (`wide` | `full` | px), `tone` (`grey` | `dark` | `blue`), `fx` (`rise` | `gradient` | `sweep`), `height` (`small` | `medium` | `large` | `huge`). All whitelisted by `section_class()` / `section_style()` because they land in `class` / `style`; all in `_NON_TEXT_KEYS`; the first four deliberately *not* fields in `BLOCKS` so the editor renders one set of controls for every type.

**Section effects.** `fx` is the exception to that last sentence — and `height` is the second one: `section_class()` emits both for any block, but only the blocks that *declare* them get the dropdown (`fx` on `stats` and `rich_text`, `height` on `spacer`), which is what limits each to its own panel — widening either is one word in another block's optional list. `stats` also carries `count_up` (a checkbox, so nothing typed reaches a class, same reason as `hero.dark`), and both keys repeat **per item**: `EDITOR["items"]["stats"] = ["value", "label", "fx", "count_up"]` and `stats.html` resolves each `<li>` as `item.fx or section.fx`, running the per-item value through `section_class()` itself rather than a second whitelist. `count_up()` splits the first whole number out of a figure (`"Up to 5 PB"` → `(5, "Up to ", "5", " PB")`) so only the digits roll; the digits stay in the HTML and CSS draws the counter beside them. All four effects are pure CSS (§9). `--w` is the content measure override, `--w-def` the block's own designed measure (§6 explains the specificity trap that made `--w-def` necessary).

**The two blocks that are not content.** `spacer` (`([], ["height"])`) is blank height an editor picks from `HEIGHTS`; `divider` (`([], [])`) is one `<hr>` inside `.wrap`, so the universal `width`/`align_box` already shorten it and move it and it needs no field of its own. `spacer` is in `MD_SKIP`; `divider` is the one `blocks_md()` branch that is punctuation (`---`). Both are droppable inside a column. The whole cost of them is CSS: `.section{padding:80px 0}` makes an empty section 160px tall, and inside a column `.column>.section+.section{padding-top:24px}` (0,3,0) beats a bare `.spacer` — so the rule group zeroes both and ties that specificity with `.column>.section.spacer`, and the four heights are scoped `.spacer.sp-*` rather than bare like `.fx-*`, since another block could one day declare `height`. `canvas.css` outlines a spacer so the editor can see a section that is by definition invisible.

**Special cases inside `render_blocks()`:** `post_list` (queried at render time, hands the template `posts` + `pt_slug` from the DB row, plus `cols` from `_cols()`), `warranty_check` (looked up from `?sn=` at render time; `edit=True` never queries), `columns` (the one block that holds blocks: `data.cols` is a list of lists, one level deep, `col(n)` callable, `widths` "50/25/25"). `edit=True` also hands templates `fe()` markers (`data-b` path, `data-f`, `data-r/data-i`, `data-rich`) that cannot reach the public render. A malformed block re-raises on the public site and renders an "unfinished" notice on the canvas.

**Two flatteners:** `blocks_text()` (deterministic reading order via `_TEXT_ORDER`, for admin search and the public API `text`) and `blocks_md()` (one branch per type; the body of every `.md` twin and `llms-full.txt`). **Test gates when adding a block:** `test_inserter_metadata_and_seeds`, `test_blocks_md_covers_every_block` and `test_every_block_type_has_a_template_that_renders` (every seeded type, both modes — a missing template is a 500 on the public page and nothing asserted one existed before 2026-09-15) always; `test_editor_metadata_covers_every_block` for a new widget or repeater; `test_render_blocks_uses_template` for the markers (tight against the tag). One consequence of the shared document worth knowing here: a new string key that is not in `_NON_TEXT_KEYS` becomes shared, word-by-word text in the editor by that fact alone, while a repeater's rows ride as one value. Full checklist: `/new-block`.

**Rules of thumb:** `hero` is the only block with an `<h1>` (`post.html` skips the page head when a post starts with a hero *or* a columns block); variant switches are checkboxes (`hero.dark`, `testimonial.dark`), never free text; raw HTML in `rich_text`/`embed_html` is trusted staff-only (`# ponytail:` add `nh3` if untrusted authors appear).

## 6. Auth

- Admin API: `Authorization: Bearer <access token>`; `POST /api/admin/v1/auth/login|refresh|logout`, `GET /auth/me`. 401 bad credentials; 403 for a GoTrue user with no `users` row (authentication ≠ authorization).
- Browser admin: same login through a form; tokens in the signed session cookie (SameSite=Lax, Secure on https), `auth._session_token()` refreshes silently, and a refresh that loses to a concurrent one leaves the session alone. Every POST carries a per-session `csrf` field checked by `ui_required`; `next` accepts relative same-origin paths only. The token is minted **only for `admin_ui` requests** — `_globals()` is an `app_context_processor`, which is app-wide despite its blueprint, so the `request.blueprint != ui.name` guard is what keeps anonymous public pages from answering with `Set-Cookie` and becoming uncacheable. Do not remove it; no public template reads those globals.
- Roles: `editor` (content, media, leads, warranty add/edit) < `admin` (delete, post types, settings, users, redirects, warranty delete).
- Sign-in uses a throwaway anon client, never the service-role client.

Decisions that are easy to undo by accident:

- **Header is white** with the logo in its own colours (client, 2026-09-08); the footer stays dark and knocks the logo out.
- **Logo is a fixed box, not a fixed height**: `.brand img{width:150px;height:22px;object-fit:cover}`, one rule for header and footer (2026-09-10). The mock's `height:22px;width:auto` counted an uploaded file's own padding as logo — the live 2172x724 PNG has its wordmark in the middle 271 rows and rendered at 8px. `cover` crops the box full so the file's margins stop mattering; the 6.8:1 box shaves ~1px a side off the original 180x26 artwork, and a square logo drawn edge to edge loses its top and bottom.
- **Footer socials are a `<ul class="social">` under the brand, not links in the Contact column** (2026-09-11). `seo.site()["social"]` is `[{url, name, icon}]` via `_social()`/`SOCIAL` — registrable-host match, so `www.`/`in.` prefixes and the `twitter.com`→`x.com` alias all land; an unmapped host keeps its hostname and an empty `icon` and renders as text. `jsonld()` unwraps it for `sameAs`, which stays a list of strings. **`hidden` does not hide an inline `<svg>`** — the UA rule is HTML-namespaced — so `.site-footer svg[hidden]{display:none}` is load-bearing or the sprite reserves 300x150 above the row (`admin.css:124` is the `.admin`-scoped twin). simple-icons glyphs are solid: `fill:currentColor`, not the admin sprite's stroke. These are the **only** public links with `target="_blank"` (client, 2026-09-11); `rel="me noopener"` already covers the opener risk.
- **Mega panel is CSS only** (`:hover`/`:focus-within`, `:has()` to switch groups, 8-group ceiling), fed by `service_nav()` over `db.tree("service")`.
- **Hero rotator is CSS** (`--n`/`--i`, one keyframe set per picture count: 2 and 3 exist). `.hero-dots` sits *outside* `.hero-slides` — that element carries the `float` loop and anything inside it bobs with the picture; do not move the dots back in (2026-09-10).
- **Section effects are CSS** (`fx-rise`, `fx-gradient`, `fx-sweep`, `fx-count`): `@property --cv` + `counter()` for the roll, all of it on the **document timeline** — they play once as the page loads, the same in every browser. Four things not to undo. (1) **No `animation-timeline: view()` on these.** Both scroll drafts failed, in opposite directions: the whole group inside `@supports (animation-timeline: view())` did *nothing* in Firefox ≤143, which parses the property but cannot resolve `view()` and froze each animation on its opening frame; base rules plus a trailing `@supports` that only re-timed them then broke the content, because a scroll timeline pins the animation to where the reader *is* — a section in the first viewport loads part-way through its own range, and the Numbers band under the hero rendered **270 for a figure typed as 300** in every browser that resolves `view()`. (2) **No `var()` in the counter's keyframe** — Firefox will not interpolate one and the figure jumps 0 → 300 in a single frame, while Chrome tweens it, so the bug does not show in a Chromium screenshot; `--cv` runs a literal `0 → 1` and `counter-reset: cv calc(var(--to) * var(--cv))` applies the target. (3) The sweep is a **background**, not an `::after` with `z-index:-1`, which would sit behind the section's band. (4) **One effect, one element** — `animation` is a single property, so the counter is animated on its own `.cr` span or it silently replaces the sweep and the gradient on the same `<strong>`.
- **`prefers-reduced-motion` is the LAST block in the file and says `!important`** (2026-09-10). `@media` adds no specificity; from where it used to sit it lost to the block groups below it, and the hero kept moving for a reader who had asked it not to.
- **Archive grid is `auto-fill`, page deck is `auto-fit`**; four archive shapes scoped to `.arch-body` (`pl-product`, `pl-service`, `pl-event`, `pl-datasheet`); `pl-service` unpins `grid-column` under 700px.
- **Long words wrap**: `overflow-wrap:break-word` on `body`, `anywhere` on content-sized boxes only.
- **The quote form is grey, not black** (client, 2026-09-10): `contact_form` has two skins across three kinds — `quote` and `career` both take `.cf-grey`, `contact` the plain white card. The mock draws the Contact screen's form on a black card; do not restore `.cf-dark` from it.
- **The partner logo strip is full colour, and the mark grows on hover** (client, 2026-09-16): the mock runs it at `filter:grayscale(1)` + `opacity:.7` with colour back on hover; do not restore either from it. The tiles are `<div class="card">` (a partner has `has_pages=false`, so `_card.html` gives it no `<a>`), which is why `a.card:hover` cannot reach them and the strip needs its own `:hover` rule — and why that rule had to be added to the `prefers-reduced-motion` block by hand, beside `a.card:hover`. The effect is `scale(1.14)` over `.3s cubic-bezier(.2,.7,.3,1)`, **not** the site's `translateY(-2px)`: a logo has no card edge to rise off, so the 2px lift the first pass used was invisible and the client asked for bigger and smoother. `transform-origin` stays centre so the grid never reflows, and `position:relative;z-index:1` only lifts the growing tile over its neighbours' edges.
- **`post_list` has an "Items per row"** (`per_row`, 2026-09-16): `""` = the old `auto-fit`, `"even"` = `even_cols(len(posts))`, `"2"`–`"8"` pinned. Emitted as `pl-cols-<n>` from `_cols()`, **never** from the block data, and in `_NON_TEXT_KEYS`. Applies above 760px only and not inside a `.column`.
- **Price rides on the Buy button** (`Buy · ₹ 10,000`), never a detail tile; `rupees()` groups Indian-style.
- **Product page has no hero**: the page head *is* the design's detail header.
- One `_card.html` macro for archive, page lists and post children; `actions=True` (archive only) turns product/datasheet/service cards into `<div>`s with linked titles because an `<a>` cannot nest.

The autosave itself is the one unlogged write in the app. Above the filters, a shut `<details>` from `throttle.connection()` reports what the *From* column will record, what opened the connection, whether that peer is inside `TRUSTED_PROXIES` and the raw forwarding headers — the screen's answer to "is this column real", which with two ingresses depends on which one you came in on.

**Stress test** (`/admin/stress`, `admin/stress.html`, `iopstor/stress.py`, **owner-only**): an internal load-and-abuse simulator. Enter visitors + attackers + duration + a target (this instance, or another base URL so dev can load prod), press Run, watch live throughput/latency/status-histogram/429s. `stress.start()` validates + clamps and spawns a daemon **coordinator** thread; the coordinator fans the load out across `_nprocs()` **generators** (one in-process thread below `PER_PROC`≈250, else `multiprocessing` `spawn` processes sized off `os.process_cpu_count()` capped at `MAX_PROCS`=16 — one CPython process is GIL-bound, so more threads alone *lose* throughput). `_plan()` **caps real concurrency at `nprocs × PER_PROC`** — an uncapped "10000 visitors" would try to create 10000 threads (slow to start, thrashes the box on a self-test, slow to tear down, no extra throughput), so over the cap the numbers are scaled down and the run records both requested and `*_run` driven counts (shown in the panel). Each generator runs its share of `_worker` threads (stdlib `urllib`) and writes its own `parts` row; the coordinator `_merge_parts()` sums them into the one `runs` row the poll reads, and `GRACE` seconds after the deadline/Stop it `terminate()`s the child processes (a worker blocked in a request can't be interrupted, so this ends a heavy run in ~2s instead of a whole `REQ_TIMEOUT`). Both tables are in a sqlite file on `/dev/shm` (WAL) — throttle.py's cross-worker trick, because the poll (`GET /stress/progress/<id>`, a GET) can land on any of the 30 workers, and many generators write at once. `spawn` (not fork) so a worker's forked state is never copied; children are daemon (die with the worker) and self-stop at the deadline. Measured on an 8-core box vs a scalable target: ~900 req/s one process (falling with threads) → ~1200 multi-process (rising with load) — the win is that it scales the right way, not a fixed number; the target (PostgREST pool 10) is the real wall. `STRESS_DB` is a constant, deliberately **not** an env key, so it stays out of `x-app-env` and the container-env test. **The gate is a single email (`STRESS_OWNER`), not a role** — the first identity-level gate in the app: nav row behind `{% if is_owner %}`, routes behind `owner_only` (= `ui_required("admin")` then `abort(404)` for anyone else, a 404 so a stranger learns nothing, like the office gate). Attackers are **non-destructive** (missing paths, missing media, warranty `?sn=` reads, honeypot-filled lead POSTs that `public.py` accepts and drops) so nothing writes a row of ours; login brute-force is left out on purpose (it would pollute the target's Activity and lock the source IP out). Because a run changes no row of ours, `stress_run`/`stress_stop` are in `AUDITED` as deliberately-not-recorded, like preview/canvas. Measured offline by `test_run_load_hits_a_real_server_and_the_honeypot_leaves_no_row`.

**Restore** writes the "was" half back through the ordinary helpers, so the restore is itself logged. It stays **one button per entry, below all the rows**, however many rows a page edit produces: it puts the whole `blocks` array back, and a button per row would promise something it does not do. `_restorable()` is the rule worth knowing: an `update` always, a `delete` **only for `posts`** (that is a trash move, the row is still there). Every other delete is real and re-creating the row would be a lie — a deleted user's GoTrue account is gone, a media row would point at a removed bucket object, `warranties.serial_key` is `GENERATED ALWAYS`, a taxonomy's terms cascaded. Restore has three writers because `db.update()` is keyed by `id`: `settings` and `menus` go through `set_settings()`/`set_menu()`. It is also the one caller that deliberately does **not** pass `if_unchanged` — a restore is an intentional overwrite of whatever is there now, which is the whole point of the button.

**Not everything is a row write.** `db.py` cannot see a change that touches no table of ours, which is how a password change went unrecorded: `auth.set_password()` talks to GoTrue and writes nothing. Those need an explicit `db.audit_event()` — `password_changed`, `password_reset`, `login`, `logout`, `login_failed`, `login_blocked`, `create_admin`. `_audit(system=True)` is the one path that runs off a request (and must skip `client_ip()`, which reads `request`), used by `flask create-admin` alone: `seed` and `import-media` write content, this creates a credential. **`test_every_route_that_can_change_something_is_accounted_for`** walks `url_map` and fails until every new non-GET route is written down as logged or deliberately not — the gap existed because nothing checked.

**The recording lives in `db.insert()`/`update()`/`delete()`, not in the routes** — a write path added later is logged without anybody remembering to. `_audit()` returns immediately when `has_request_context()` is false, which is the entire `flask seed` / `import-media` exclusion, **and again under `TESTING`** -- the live suite runs against the real Supabase and the append-only trigger means nothing can take its `zz-test` rows out again (`migrations/purge_test_audit_rows.sql` clears the runs that happened before the guard). It swallows its own failures (the content write already succeeded, and the app must run before `0008` is applied), so a gap in the log is possible and only a logger warning names it. `update(..., action=…)` relabels a trash move as `delete`. Deliberately not recorded: reads; session and token mechanics (the CSRF token, the cookie, and the refresh rotation `_session_token()` does on every admin GET — `POST /auth/refresh` included); refusals other than a blocked login; the bucket and GoTrue halves of an upload/delete/user-create, each of which sits beside a logged row write; rows a Postgres cascade removes; and `public.py`'s `redirects.hits` bump, the only `.update()` chain left outside `db.py`. A blocked login is recorded **once, at the crossing** — `throttle.record_failure()` returns `True` only for the attempt reaching the limit, because logging from `retry_after()` would write a row per attempt for the whole window and let anyone hammering a locked login fill the log at will.

**IST everywhere in the admin**: `db.ist()` / `db.ist_input()` registered as Jinja *filters* in `create_app()`, a fixed `+05:30` rather than `zoneinfo` (no DST in India, no tzdata in the slim image). `admin_ui._as_ist()` stamps the offset onto the publish-date input — at that input only, never in `db.parse_dt()`, which the JSON API shares and where a missing offset must still mean UTC.

**Preview** (`POST /admin/preview`): the real `post.html` in the real `base.html` from the unsaved form, `noindex`, no analytics (`{% if site.ga_id and not preview %}`), device widths 1440/834/390 by scaling the iframe. **It follows a colleague's typing** (PRs #73, #74; TECHNICAL §12.2): a peer's prose reaches `MODEL` through an offscreen Quill in the parent page when no editor is mounted (`mirrorProse()`), so Preview and Publish are never an edit behind; a remote update repaints by swapping `#main` inside the existing document on a shared 500 ms beat (`pvUp` is what keeps that surgery out of the edit canvas, which has a `#main` of its own), so the reader's scroll position survives where `srcdoc` reset it several times a second. Between full renders the head, header, nav and footer stay as they were; they come from Settings and Menus, which the page editor cannot change.

**The `[hidden]` rule:** `.admin [hidden]{display:none!important}` — author `display` rules beat the UA's `[hidden]`, which once showed two panes at once.

Deployment-side, not in source: `apply_migration()` takes no lock, which within one stack no longer matters (one `migrate` service, however many `app` replicas) but would if two stacks ever shared a database — `pg_advisory_xact_lock` in that function is the fix; the container runs as root; `/healthz` is liveness-only, so nothing polls Supabase's health. The ones an agent trips over: HS256-only JWT; hierarchy index < 2000 posts per type; one sitemap < 5000 URLs; honeypot-only spam control; raw HTML trusted; `execCommand` editor; rotator keyframes for 2 and 3 pictures only; per-request caches, so `post_types` and `settings` cost a round trip each per request; a redirect's `hits` loses counts under parallel visits; PostgREST calls wait up to 120 s; `checkout` and `index` are reserved slugs; counting rolls whole numbers only and refuses grouped ones; a section effect plays at load, so one far down the page has finished before the reader reaches it; the counter needs `@property` (Firefox 128+) or the figure reads 0; `_html_md()` is regex, not a parser; `/media/` is a reserved first segment, its files are read whole into memory and have no server-side cache; `DummyGateway` moves no money; **a failed `audit_log` write is swallowed**, so the log can have a gap the log cannot report (watch the logger warnings); `audit_log` has no retention job and stores a page's whole old and new `blocks` array on every save; a restore is not pre-checked against media or a parent that has since been deleted, so it surfaces as a 502 through `_pg_error`; the save-conflict guard covers **`posts` only** (`settings` and `menus` write through `set_settings()`/`set_menu()`, are not keyed by `id`, and still overwrite silently), is skipped when `_save()` finds no `changes` so a terms-only edit from a stale form is unguarded, and reports a conflict once before letting the next Save overwrite; the rich_text blocks Quill refuses (after `0011`: NAS's specification table, Contact Us, the About Us founders grid, the Testing pages) keep the original editor, so co-editing will not reach them either — the fix is a block type per section, as `points`/`definitions` were, and a Settings-backed block for Contact Us, not a bigger Quill; a Quill block's first save rewrites it once (normalisation) and Activity reports it; a peer adding, removing or moving a section repaints the whole canvas and costs the local caret (typing does not — y-quill applies that straight into Quill); a repeater's rows ride as one value, so two people in two rows of **one** block still lose a side, which is the largest remaining gap in "both sets of words survive"; a move is delete + fresh insert, so a peer typing into a section as it moves loses that sentence; a batch carrying a structural change *and* prose applies `fromY()` and returns, so that batch's prose reaches MODEL only on the next one (publishing from Preview used to be a page behind for the same family of reasons; `mirrorProse()` closed that); Preview's `#main` swap leaves the head, header, nav and footer as they were at the last full render, so a Settings change made in another tab shows on the next Edit/Preview switch; two first-ever opens of a page milliseconds apart can still double-seed the document; a `post_sessions` row on a page nobody ever reopens stays pending, because the flush is opportunistic and there is no sweep command; presence is advisory and its *where* is best-effort (a caret position ages out after a minute because the editor raises no event when focus leaves a field; the caret broadcast is debounced to 250 ms, i.e. up to 4/s per editor against the tenant's `max_events_per_second`, and the five capped reconnects each spend one of the ~5-per-minute presence events) and **nothing tests the channel end to end** — the offline suite covers the room name, the colour's stability and the proxy's own edges (it refuses without a session or csrf, pins the apikey, and normalises a status the browser's transport would throw on), the rest is two browsers by hand; the transport is selected through minified vendor internals (`realtime.socketAdapter.socket.getLongPollTransport()`), so a supabase-js bump can move it and break collaboration quietly; the container `HEALTHCHECK` needs `bash`, `grep` and `head` in the image (verified present in `python:3.13-slim`, but a base-image change is the thing that would quietly break it); the stress-test run fans out across `_nprocs()` processes (× threads) with real concurrency capped at `nprocs × PER_PROC`, lifting throughput by ~cores (not 10k/s on modest hardware, and the target's PostgREST pool caps it first); the coordinator and its children live in whichever worker took the request, so a recycled worker freezes the run at its last flush; its only target guard is the scheme (no SSRF allow-list — owner-only behind the office-only admin, dev→prod on the LAN is the point); and two Run clicks start two runs at once (one owner, their own doubled load).
